# LIBRARY MANAGEMENT APP

## Software Requirements Specification (SRS)

---

## Task 2: Major Stakeholders

### 1. Students / Library Users
- Search for books.
- Check book availability.
- Borrow books.
- Return borrowed books.
- View their borrowing details.

### 2. Librarian
- Add new books.
- Update book details.
- Remove books.
- Manage borrowing and returning records.

### 3. Library Administrator
- Manage the overall library system.
- Manage users and librarians.
- Monitor library records and reports.

### 4. College Management
- Monitor library usage.
- View reports and statistics.
- Ensure effective library management.

# Task 3: Requirements

## 3.1 Functional Requirements

Functional requirements describe what the Library App should do.

| ID | Functional Requirement |
|---|---|
| FR1 | The system shall allow students to search for books. |
| FR2 | The system shall display book details such as title, author and availability. |
| FR3 | The system shall allow students to borrow available books. |
| FR4 | The system shall allow students to return borrowed books. |
| FR5 | The system shall allow librarians to add new books. |
| FR6 | The system shall allow librarians to update book information. |
| FR7 | The system shall allow librarians to remove books. |
| FR8 | The system shall maintain borrowing and returning records. |
| FR9 | The system shall allow authorized users to log in. |
| FR10 | The system shall display appropriate messages for successful or unsuccessful operations. |

## 3.2 Non-Functional Requirements

Non-functional requirements describe how well the system should work.

| ID | Requirement |
|---|---|
| NFR1 | Usability – The application should be simple and easy to use. |
| NFR2 | Performance – Search and other operations should respond quickly. |
| NFR3 | Security – Only authorized users should access restricted functions. |
| NFR4 | Reliability – The system should maintain accurate library records. |
| NFR5 | Availability – The application should be available whenever the library requires it. |
| NFR6 | Maintainability – The system should be easy to update and maintain. |
| NFR7 | Scalability – The system should support an increasing number of books and users. |

# Task 4: Basic SRS

## 4.1 Introduction

### 4.1.1 Purpose

The purpose of the Library Management App is to provide a simple system for managing books, students, borrowing and returning activities in a library.

### 4.1.2 Scope

The application will allow students to search and view books, check availability, borrow and return books. Librarians will be able to manage book information and maintain library records.

---

## 4.2 Stakeholders

- Students / Library Users
- Librarians
- Library Administrators
- College Management

---

## 4.3 Functional Requirements

The system shall:

1. Allow users to search for books.
2. Display book details and availability.
3. Allow students to borrow available books.
4. Allow students to return books.
5. Allow librarians to add books.
6. Allow librarians to update book details.
7. Allow librarians to remove books.
8. Maintain borrowing and returning records.
9. Provide login for authorized users.

---

## 4.4 Non-Functional Requirements

The system should provide:

- **Usability:** Simple and user-friendly interface.
- **Performance:** Fast response to user requests.
- **Security:** Protection of user and library data.
- **Reliability:** Accurate and consistent records.
- **Availability:** System should be accessible when required.
- **Maintainability:** Easy to modify and update.

---

## 4.5 User Roles

| User | Main Responsibilities |
|---|---|
| Student | Search, view, borrow and return books |
| Librarian | Manage books and borrowing records |
| Administrator | Manage the overall system |
| Management | Monitor library activities and reports |

---

## 4.6 Expected Outcome

The Library Management App should make library operations easier, faster and more organized by providing a centralized system for managing books and library users.
